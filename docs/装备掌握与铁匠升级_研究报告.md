## 二、真实流程逆向结果（字节码级确认）

### 掌握（背包界面"掌握"按钮）
调用链与关键函数（均在 SwordGame.upk）：

```
SwordXpBar.OnBuyMasteryBttn (554B)          ← "购买掌握"按钮（弹窗确认路径）
SwordXpBar.MasterCurrentItem (563B)         ← 经验条满时的"掌握"按钮
  ├─ 扣款：对玩家货币字段做减法（金币/筹码由 SpeedUpCurrencyType 选择）
  ├─ GiveXp(Bool bTest, Int XP)             ← 玩家经验增加（SwordPlayer.GiveXp）
  ├─ OnMasteredItem()                       ← SwordPlayer.OnMasteredItem(78B)
  │    └─ AvailableStatPoints += LevelStatPointsPerMastery   ← 技能点/属性点 +N（N 为可配置字段）
  └─ 上报事件 "ItemMastered"（%item%/%Amount%/%Currency%）
```

对照：`SwordPC.SetPlayerMasterAllItems` = `PlayerPawn.MasterAllOwnedItems()` 的薄包装 →
`QuickMasterItem(SetAllToLevel, bIngoreCurrentXPCheck, MasterCount, StartingItemLevel, Item)`（792B）

跳过了扣款与属性点（与实测一致）。

关键数据结构：
- 物品对象 `SwordInventoryItem`：`XP`（累计经验）、`CurrentLevel/BaseLevel/HiddenLevel`、
  `CostToMaster(Int XpLeftInItem)`、`GetMasteryXP()`、`CanPlayerMasterItem(Object P)`
- 玩家 `SwordPlayer`：`PlayerInventory`（数组）、`SelectedInventoryIdx`、`AvailableStatPoints`、
  `LevelStatPointsPerMastery`（每掌握一件 +N 点）、`LevelStatPointsPerLevel`、
  `CurrencyStruct.Current`（金币，`SetPlayerGold` 即写这里）
- `SwordPC.SetPlayerLevel(Int)` 实测会给 `AvailableStatPoints` 按等级差加点！

### 铁匠升级
```
SwordPlayer.StartForgingItem(Object Item)    ← CanForgeMoreItems/CanForgeItem 校验 →
                                               CalculateItemForgeCost 算价 → 扣款(推测) →
                                               StartCountdownTimer("ForgeItem","Item") 启动倒计时
SwordPlayer.CompleteForgingItem(Int ForgeIdx)← IsBeingForged 校验 → LevelUpItem（装备等级+1！）→
```

## 三、卡住的一层：脚本完整性校验

为把上述流程做成一键批量，需要改写某个 exec 函数的字节码（循环调用真实流程）。
实测发现：**修改现有函数的脚本字节码（哪怕 6 个 NOP）→ 游戏启动即退**；
而修改导出表（加 exec 标志位）→ 完全正常。即引擎/移植版对脚本字节码有完整性校验，
对导出表没有。

**已验证可行的绕行路线**：用"新增导出对象"的方式追加一个**全新函数**（不动任何现有字节码）——
这正是本会话在 Startup_LOC_CHN.upk 上成功用过的包手术方法（pkgmerge4）。
需要：名字表加函数名 + 导出表加一个 UFunction（Outer=SwordPlayer，flags=Exec|Public|Defined）
+ 函数数据（48B 头 + 字节码 + 15B 尾）。字节码内容 = 遍历 PlayerInventory 循环：
`CanPlayerMasterItem 门控 → CurrencyStruct.Current -= CostToMaster → GiveXp(false, it.XP) → OnMasteredItem()`。

**风险与工作量**：需要先按 skill 的标定流程把 v868 的比较/跳转/数组长度等操作码校准
（本会话已校准：Let=0F、Context=19、VF=1b、DynArrayElement=10、JumpIfNot=07、Return=04、End=16、
EOS=53、False=25；未校准：算术与比较运算、StructMember 的 v868 精确格式——注意 v868 与 v864 的
操作码表有非均匀偏移，不可直接套用）。另外 v1 实验发现 SetupEngagementNotifies 会被启动流程调用，
选宿主/新函数时必须避开所有会被自动调用的函数。
