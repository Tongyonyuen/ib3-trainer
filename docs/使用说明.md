无尽之剑Ⅲ修改器 —— 使用说明（v1.0.0 · 2026-10-08）
========================================
项目主页：https://github.com/Tongyonyuen/ib3-trainer
（本成品包不含 ib3_addrs.ini / ib3_paths.ini / ib3_mailbox.json —— 这三份是每台机器各自生成的本机
  状态，首次运行时会自动创建，故不随包分发。）

【适用环境】
- Windows 10 / 11（已在 3840x2160 @125% 缩放实测，低分辨率小屏亦自适应）
- 无尽之剑3 移植版（必须为同一版本；版本不符时修改器只会失效/拒绝，不会乱改）
- 建议先备份存档：文档\My Games\Infinity Blade III\SwordGame\Cloud


【首次使用（重要）】
1. 把本文件夹所有文件解压到任意目录（路径不要有特殊符号）
2. 双击运行「IB3训练器2.exe」
3. 点左下角「游戏目录…」→ 选择【Infinity Blade Launcher.exe】所在的文件夹
   （通常是 你的游戏目录\Binaries）
4. 修改器会自动完成两件事：
   a. 记住游戏位置（以后直接点「启动游戏（中文）」）
   b. 把随包的 SwordGame.upk 替换到
      游戏目录\SwordGame\CookedPCConsole\SwordGame.upk
      （原文件自动备份为 SwordGame.upk.orig）
   ※ 替换 upk 是必须的：发放物品 / 掌握升阶等命令依赖它才能生效
   ※ 若提示“游戏正在运行”——请先关闭游戏再重新选择游戏目录
5. 点「启动游戏（中文）」→ 启动器出现后会自动帮点 Play → 游戏进入中文版
6. 游戏运行中修改器会自动附着（状态栏显示“已附着”），即可开始使用

★ 宝石页定位修复（本次更新）—— 上一版「点应用必定失败：写入取消（地址复核未过）」已修。

  根因：玩家对象在内存里有**多个实例**（实测同进程 8 个），其中**只有 1 个**装着宝石数组，
  其余是影子/空壳（金币与两组数组都是 0）。旧版认真身只验 vtable，而空壳与真身是**同一个类、
  同一个 vtable**——一旦背包没装载，就会挑中空壳，读出两组“干净的全 0”，
  于是**任何宝石写入都会被安全闸拒绝**（日志表现为：真身 0x… 定位到，但两组数组都不可用）。
  现在改为按“真身分”取最高分：**背包或商店任一组装载 = 4 分**，金币 2 分，筹码 1 分。
  实测能稳定选中装着数组的那个实例。

  · 提示语也改了：数组当前没装载时会明说「这是**正常状态**：玩家在关卡里 / 商店熔接室界面时
    背包会被卸载，请回到**藏身地主界面**再点一次「读取背包」」，
    不再是一句看不出该干什么的「两组数组都不可用」。
  · 顺带修正 UberBossBoostGem 的**显示值基数**：15 个加法型模板里只有它把基数写在
    BattleEffectValue 而不是 *Bonus 上，导致「当前显示值」一直少算 1000。
    现在 = 1000 + Tier × 250。
    ✅ **这条可以直接用来验证你装的版本对不对**（已实测确认）：
       把 UberBossBoostGem 改成 **Tier 0 → 游戏里应显示 1000**；
       改成 **Tier 255 → 应显示 64750**（= 1000 + 255×250）。
       若读数不是这两个数，说明包里的 exe 不是本版，请反馈。
  · 顺带修好 **14 个「档位表写成小数」的宝石模板**（ItemDropGem_1~4 / BonusComboGem_5,6 /
    FinalHitGem_5 / BreakBossGetMagic_1 / BreakBossGetSuper_1 / GlobalScaleGold,XP,RareGem_1 /
    UberTakeHitGem_2,3）：它们的 UpgradeTier 被写成 0.1/0.2/0.3，甚至 3.0/4.0/5.0 这种写法，
    公式库解析不了 → 界面上一直显示“未知类型、拒绝修改”。现在它们的 **tier 可以改了**
    （合法范围 = 档位表长度，例如 3）。
    ※ 但它们的**显示值算不出整数**（游戏里是百分比类效果，基数也不在公式库里），
      列表里显示 “?”；选「显示数值」模式会被明确拒绝并告诉你原因 —— **请用 Tier 模式改档位**。
      这是如实告知，不是故障。
  · **「填上限」按钮改为“上限说得清才填”**（详见下方 FAQ）：加法型填 255，下标型填档位表长度
    （**不再对任何宝石都填 255**），说不清的明说原因并请你手动填。
  · 宝石页每点一次「读取背包 / 重新扫描 / 应用」都会**浮窗提醒**一次：
    「若宝石列表与游戏内背包不一致，请先在游戏里存一次档（切一次场景），再点「读取背包」重新扫描」。
    原因是列表里的宝石名是拿**存档**按位对齐贴上去的，游戏内背包一旦变过（融合/买卖/换装）
    就会错位 —— 错位意味着「你看着是这颗、改的是那颗」，所以每次操作前都提醒一下。
  · **「商店刷新一轮稀有宝石」按钮不再自己弹“已刷新”**（r4 修）：以前它在注入**失败**时也照样弹，
    等于替你报了个假成功。现在提示与日志都按**真实结果**来 ——「已执行：…」或「执行失败：<原因>」。
  · **每次注入都会在日志里留一行现场**（r4 新增）：命令名 + 宿主地址 + 执行器地址 +
    执行器金币 + 结果。若这个按钮在你的机器上会闪退，请把日志里这一行发回来 ——
    它能直接分清是「命令根本没送到游戏」还是「游戏自己执行时崩的」，省一整轮来回。
  · 本次改动都在宝石页 + 注入提示，其它功能逻辑未动。

★ 宝石页写入链路（上一版）—— “改了没反应”的问题已修好，现在能真正改到存档。

  根因两条，都已修：
  ① 训练器读一次就把地址记下来，之后写的是**已经失效的旧地址**。游戏会把宝石数组
     重新分配（一次会话里实测挪了 5 次），而回读校验照样“通过”，于是表现为
     「日志说写入成功、游戏里毫无变化」。现在**每次写入前都会当场重新定位**，
     对不上就拒绝写入并提示你重新读取。
  ② 加法型宝石的 GemTier **只在 CookedGemVar=50（进过熔炉）时才被游戏承认**。
     cook=0 的宝石，游戏在切场景重建背包时会把 tier 归零。现在训练器改 tier 时
     会**自动把该宝石标记为“已融合”**。
     受影响的 15 个模板：UberAttackGem / UberHealthGem / UberShieldGem / UberMagicGem /
     8 种元素 Uber*Gem / UberElementalAttackGem_100 / RainbowElementalAttackGem_100 /
     UberBossBoostGem。宝石页里都能改。

  ⚠ **两条硬约束，请务必照做，否则改动会“看起来没生效”**：
  · 改完**不要先切到游戏里打开宝石界面** —— 那会让该数组卸载重载，未落盘的改动被冲掉。
  · **界面会立刻变**（实测那个数组就是游戏 UI 直接读的那一份），但要**存进存档**需要：
    切一次场景（进熔接室再退出即可），或等游戏约 50 秒的自动存档。
  · 改 tier 会把这颗宝石标记成“融合过”（CookedGemVar=50）——这是让游戏承认 tier 的
    必要条件，但**是对存档的持久改动**。想保留某颗宝石“未融合”的原始状态，改之前先记一下。

【功能总览】
· 战斗·商店：无敌 开/关、充满超能魔法、击杀当前Boss（仅战斗中）、
  金币/筹码（自动绑定，填目标值直接写入）、商店刷新、触发龙战/收藏家
· 物品发放：按分类浏览全部物品；选中后点「发放选中物品」按类型走正确通道：
  装备/藏宝图=直接发放（未拥有才发）；宝石=刷进随身商店（去商店购买即入袋）；
  材料/药水/钥匙/抽奖箱=消耗品通道直接加数量
· 宝石·背包：列出背包与随身商店里的全部宝石（模板名 / Tier / 融合标记 / 随机加成 /
  当前显示值 / 地址），可把某一颗改成目标显示值或目标 Tier。
  请先进入**能看到背包宝石的界面**再点「读取背包」——背包数组只在特定界面装载，
  界面不对时它会明确提示，不会乱猜。
· 成长：体力/护盾/攻击/魔法/等级/技能点/生命/最大生命的 读取 / 写入 / 锁定（读后写冻结）
  掌握升阶：把所有物品推到目标等级并掌握（⚠只升不降，建议先用测试档验证）
· 发现模式：通用内存扫描工作台（首扫/筛选/快照/差分/试写），供进阶排查
· 换存档：修改器会自动检测并重新绑定（日志出现“自动重新绑定完成”后再操作）

【常见问题】
Q: 提示“注入器未就绪”？
A: 等几秒让自动附着 + 自检完成；或点「立即附着」。
   若一直如此，请把日志发回（可能你的游戏版本与本文档不一致）。

Q: 物品发放 / 掌握升阶没反应？
A: ① 看日志有没有黄字「UPK 校验未通过」；有就点「部署/校验 UPK」（先关游戏）
   ② 确认游戏没在读档/加载中
   ③ 确认发放的是游戏里当前条件下允许的动作（例如装备“已拥有”时不会重复发放）

Q: 宝石页提示“写入取消：…”？
A: 这是**安全闸**在起作用，两种情况看日志那句话的后半段就能分清：
   · 「背包(+0x1FEC)/商店(+0x1FFC)两个数组当前都是空的（Count=0）」→ **不是故障**。
     玩家在关卡里 / 商店熔接室界面时，背包数组会被游戏卸载。
     回到**藏身地主界面**（能看到宝石背包那个界面）再点一次「读取背包」，然后立刻改。
   · 「…已失效（游戏重分配过）」→ 游戏把数组重新分配过了，旧地址不再有效。
     重新点一次「读取背包」再操作即可。
   两种情况下都**不会**写到错误的位置——宁可不动，也不乱写。

Q: 点「填上限」没反应，提示“上限不清楚”？
A: 这是**有意的**（本版新增）：**上限说得清才自动填**。
   · 加法型（模板有 RecipeBoostAmount）→ 上限 255（GemTier 是 uint8 字段，255 就是硬上限）
   · 下标型（模板有 UpgradeTier[]）→ 上限 = 档位表长度（如 FireGem 是 5、ItemDropGem_1 是 3）
   · 模板两者都没有（以及商店里的「(空槽)」）→ 本页**不知道**它的上限，
     就不会拿 255 之类的数字顶替（上一版会填 255，看着很确定、其实是猜的），
     提示里会说明原因，请自己填一个目标值。
   另外：「显示数值」模式下，若模板没给 MaxRandomAddPct（pct 能掷到多少不知道），
   或基数没查到，也会判为“说不清”——因为那种情况下的上限同样是算不出来的。

Q: 宝石改完界面变了，但重进游戏又变回去了？
A: 落盘没赶上。按上面的硬约束：改完**立刻切一次场景**，中间不要打开宝石界面。
   另外注意该宝石的模板是否属于“加法型 15 种”之列——不属于的话游戏会忽略它的 tier。

Q: 某项成长属性显示“未定位”？
A: 本版应全部自动绑定。若出现，说明结构偏移与你的游戏版本不符——
   可临时用该行的「定位」按钮手工绑定（填游戏内当前值→定位→游戏里改变数值→填新值→再定位），
   并把日志发回，我会按你的版本修正偏移。

Q: 换电脑 / 换游戏目录？
A: 重新点「游戏目录…」选择即可（upk 按 md5 判断是否需要替换）。
