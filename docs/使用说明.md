无尽之剑Ⅲ修改器 —— 使用说明（v1.1.9 · 2026-10-10）
========================================
项目主页：https://github.com/Tongyonyuen/ib3-trainer
（本成品包不含 ib3_addrs.ini / ib3_paths.ini / ib3_mailbox.json —— 这三份是每台机器各自生成的本机
  状态，首次运行时会自动创建，故不随包分发。）

【适用环境】
- Windows 10 / 11（已在 3840x2160 @125% 缩放实测，低分辨率小屏亦自适应）
- 无尽之剑3 移植版（必须为同一版本；版本不符时修改器只会失效/拒绝，不会乱改）
- 建议先备份存档：文档\My Games\Infinity Blade III\SwordGame\Cloud


【首次使用（重要）】
1. 把本文件夹所有文件解压到任意目录（路径不要有特殊符号）
2. 双击运行「IB3训练器2.exe」
3. 点左下角「游戏目录…」→ 选择【Infinity Blade Launcher.exe】所在的文件夹
   （通常是 你的游戏目录\Binaries）
4. 修改器会自动完成两件事：
   a. 记住游戏位置（以后直接点「启动游戏」）
   b. 把随包的 SwordGame.upk 替换到
      游戏目录\SwordGame\CookedPCConsole\SwordGame.upk
      （原文件自动备份为 SwordGame.upk.orig）
   ※ 替换 upk 是必须的：发放物品 / 掌握升阶等命令依赖它才能生效
   ※ 若提示“游戏正在运行”——请先关闭游戏再重新选择游戏目录
5. 点「启动游戏」→ 启动器出现后会自动帮点 Play → 游戏进入中文版
6. 游戏运行中修改器会自动附着（状态栏显示“已附着”），即可开始使用


【本版重点（请针对性测试）】


★ 全招架宝石：改成「普通招架即可招架住所有攻击类型」（v1.1.9 新增）

  原版这颗宝石（`GreatParryAllGem`）的效果是 `BE_VarAdd_GreatParryAll`：它写进
  `SwordPlayer.ModVars[81]`，而全游戏**唯一**读它的地方是 `SwordBoss.DoAttackActionAnim.NoParry` ——
  那里把 `MinParryTypeValid` 抬到 **2（高水平招架）**。所以**必须高水平招架以上**才判定成功。
  IB2 的同类宝石（完全招架宝石 `DualGem_5`）用的是另一条效果 `BE_Time_ParryAllAttacks`，
  **普通招架即可**；IB3 把这条效果降级给了一个发不出来的废弃药水模板 `Potion_ParryAll`。

  本版把开关做进「战斗·商店」页：点一下把宝石模板里那一行的效果换回 `BE_Time_ParryAllAttacks`，
  再点一下还原。**实测**：普通招架（HUD 出"招架"/"招架攻破"）即可招架住**腿部攻击**与
  **手部非武器攻击**，且**跨场常驻**。

  · 改的是**两份配置文件**（UE3 里用户侧配置在默认配置之后加载、会覆盖游戏侧）：
      用户侧 `文档\My Games\Infinity Blade III\SwordGame\Config\SwordGems.ini`
      游戏侧 `<游戏目录>\SwordGame\Config\DefaultGems.ini`
    界面会把两份路径都显示出来 —— 本机有两份安装，"改了哪一份"必须一眼可见。
    生效判据是**用户侧优先**：用户侧改了就算开启（游戏侧那份可能仍是原版值，状态栏会标"未同步"）。
  · **必须重启游戏**才生效（配置只在启动时读一次）。游戏在跑时点按钮会被直接拒绝。
  · 副作用（**有意保留**）：宝石图标会变色（颜色按效果枚举取色），说明文字从"全部招架"变"完全招架"
    —— 正好当"这颗被改过"的提示。
  · 每个被改的文件**首次**改写前会自动备份为同目录 `*.ib3bak`（只备份一次，不覆盖你已有的备份）。
  · 手动等效做法：把 `SwordGems.ini` 里 `[GreatParryAllGem SwordInventoryItemGem]` 段的
    `BattleEffect=` 改成 `BE_Time_ParryAllAttacks`。⚠ **别用全局替换** —— 同一文件里
    `Potion_ParryAll` 段的 `BattleEffect` 值恰好也是这个，替换错了会写坏药水段。

★ 宝石：改一颗不再连坐同类（v1.1.2 修）

  症状：背包里有 3 颗状态相同的同类宝石（例如 3 颗未融合的 UberAttackGem），
  只改其中一颗，**三颗一起变**；而且改完三颗状态仍相同，之后每次改都继续连坐。

  原因：写入时按"内容相同就一起写"来筛选 —— 本意是"同一颗宝石在内存里有 2~3 份镜像，
  要一起写否则可能白改"，但"同一颗的另一个镜像"和"另一颗恰好状态相同的宝石"用内容分不开。
  而未融合的加法型宝石**永远**是 tier=0/cook=0，同模板必然内容相同 ⇒ 必然连坐。

  现在改为按**数组内的位置**认镜像：选中哪一颗就改哪一颗，同时只连带更新它在其它镜像里的
  同一位置。

  ⚠ 若你之前依赖"改一颗顺带把同类都改掉"来图省事，请注意这个行为已经没有了。

★ 宝石：多选批量修改（v1.1.3 新增）

  列表支持多选（Ctrl 点选 / Shift 连选）。选中多颗时，会把下面那个目标值应用到**全部选中项**，
  并汇总结论（"批量完成：成功 N / M 颗"，有失败会列出前几条原因）。

  两条**禁止批量**的规则 —— 选中不合法时信息栏当场写明原因，点「应用」也会被拒：
  · **Tier 上限不同**不许批量：上限不同意味着模板/档位表不同，同一个目标值对它们不是一回事，
    硬批会写出越界值。请分开选。
  · **「显示数值」模式下算不出显示值的**不许批量（基数查不到、或档位表是小数值那类）。
    改用 **Tier 模式**，或把它排除后再批量。

  写完会**同步重画列表并保留选中**，可以连续批改，不用重新选一遍。
  （Tier 模式读档/重扫后仍建议先点一次「读取背包」再改。）

★ 自动更新（v1.1.0 新增）
- 本版起会**自动检查新版本**：启动约 3 秒后后台查一次 GitHub Releases，**不打扰你** ——
  已是最新、检查失败、网络不通都只在底部日志里留一行。
- 有新版本时弹一个小窗，三个选择：**现在更新 / 跳过此版本 / 以后再说**。
  按 Esc 或点窗口空白处 = 以后再说。**不会未经你确认就更新。**
- 选「现在更新」后：下载 → 校验（大小 / MZ 头 / SHA-256）→ 替换 → 自动重启。
  校验任何一项不过就放弃，且**不会写坏任何文件**。
- 替换是**改名式**的：旧 exe 保留为 `IB3训练器2.exe.old`，**5 分钟内改个名就能回滚**
  （把文件名末尾的 .old 去掉即可），之后会被自动清理。
- 检查频率最多 6 小时一次（上次失败则 1 小时重试）。想手动查：点标题条右侧「by Andrew Tong」
  打开「关于」，点里面的**检查更新**。
- 若修改器装在**只读目录**（例如 C:\Program Files 下），或同时开了两个修改器窗口，
  自动替换会被拒绝并改为**打开下载页** —— 这是有意的，宁可不动也不乱写。
- 状态记在程序目录的 ib3_update.ini（可手编、可删；删掉即恢复默认）。


★ 真身绑定修复（本版最重要）—— 修「首次运行四维/等级显示未定位、金币筹码是错的值」

  根因（即交接文档里那条一直未修的 bug）：内存里玩家类有多个实例，**只有 1 个装着背包/商店数组**，
  其余是空壳影子。旧版"认真身"只验 vtable + 金币区间 —— 而空壳与真身**同一个 vtable**、金币也可能非 0，
  所以撞上空壳照样"通过校验"；于是金币/筹码读到错位置，四维因全为 0 而被放弃绑定（显示未定位）。
  更糟的是"绑定是否还有效"也只验 vtable ⇒ 绑上空壳后**永远认为它活着** ⇒ 每 2 秒一次的自动重绑
  再也不触发 ⇒ **错一次 = 整场都错**，只能重启训练器。

  本版改了三处：
  ① 真身判据加入「**数组装载**」：背包装载 4 分 / 商店装载 4 分 / 金币 2 分 / 筹码 1 分，取最高分者。
     数组装载压过金币 —— 数组才是"这个对象真的装着状态"的证据。
  ② 「绑定是否还有效」从"vtable 还在"改成"**真身分仍 ≥4**" ⇒ 一旦发现绑错（或世界切换导致数组卸载），
     下一个 2 秒 tick 就自动重绑。**走进藏身地后最多 2 秒自动绑好，不需要手动操作。**
  ③ 金币锚点从"一票通过"降级为"同分时的偏好"，不再压过真身分。

  ⚠ 请重点验证（这是本次唯一无法离线验证的改动）：
  · 首次运行：启动训练器 → 启动游戏 → 进藏身地，四维/等级/金币/筹码**是否自己就对了**
  · 若附着时游戏还在读档、或你在关卡里，四维可能**短暂**显示未定位 —— 那是正常的，
    回藏身地后应最多 2 秒自动绑上（日志会写一行「未绑定真身：…」说明原因，不会再静默）
  · 命令类按钮（商店刷新 / 物品发放 / 掌握升阶）是否仍能执行。日志新增留痕：
    找不到真身执行器时会写「未找到可用的真身执行器」，此时命令**故意不执行**
    —— 宁可明确失败，也不在一个错对象上乱写

★ 宝石页定位修复（本次更新）—— 上一版「点应用必定失败：写入取消（地址复核未过）」已修。

  根因：玩家对象在内存里有**多个实例**（实测同进程 8 个），其中**只有 1 个**装着宝石数组，
  其余是影子/空壳（金币与两组数组都是 0）。旧版认真身只验 vtable，而空壳与真身是**同一个类、
  同一个 vtable**——一旦背包没装载，就会挑中空壳，读出两组“干净的全 0”，
  于是**任何宝石写入都会被安全闸拒绝**（日志表现为：真身 0x… 定位到，但两组数组都不可用）。
  现在改为按“真身分”取最高分：**背包或商店任一组装载 = 4 分**，金币 2 分，筹码 1 分。
  实测能稳定选中装着数组的那个实例。

  · 提示语也改了：数组当前没装载时会明说「这是**正常状态**：玩家在关卡里 / 商店熔接室界面时
    背包会被卸载，请回到**藏身地主界面**再点一次「读取背包」」，
    不再是一句看不出该干什么的「两组数组都不可用」。
  · 顺带修正 UberBossBoostGem 的**显示值基数**：15 个加法型模板里只有它把基数写在
    BattleEffectValue 而不是 *Bonus 上，导致「当前显示值」一直少算 1000。
    现在 = 1000 + Tier × 250。
    ✅ **这条可以直接用来验证你装的版本对不对**（已实测确认）：
       把 UberBossBoostGem 改成 **Tier 0 → 游戏里应显示 1000**；
       改成 **Tier 255 → 应显示 64750**（= 1000 + 255×250）。
       若读数不是这两个数，说明包里的 exe 不是本版，请反馈。
  · 顺带修好 **14 个「档位表写成小数」的宝石模板**（ItemDropGem_1~4 / BonusComboGem_5,6 /
    FinalHitGem_5 / BreakBossGetMagic_1 / BreakBossGetSuper_1 / GlobalScaleGold,XP,RareGem_1 /
    UberTakeHitGem_2,3）：它们的 UpgradeTier 被写成 0.1/0.2/0.3，甚至 3.0/4.0/5.0 这种写法，
    公式库解析不了 → 界面上一直显示“未知类型、拒绝修改”。现在它们的 **tier 可以改了**
    （合法范围 = 档位表长度，例如 3）。
    ※ 但它们的**显示值算不出整数**（游戏里是百分比类效果，基数也不在公式库里），
      列表里显示 “?”；选「显示数值」模式会被明确拒绝并告诉你原因 —— **请用 Tier 模式改档位**。
      这是如实告知，不是故障。
  · **「填上限」按钮改为“上限说得清才填”**（详见下方 FAQ）：加法型填 255，下标型填档位表长度
    （**不再对任何宝石都填 255**），说不清的明说原因并请你手动填。
  · 宝石页每点一次「读取背包 / 重新扫描 / 应用」都会**浮窗提醒**一次：
    「若宝石列表与游戏内背包不一致，请先在游戏里存一次档（切一次场景），再点「读取背包」重新扫描」。
    原因是列表里的宝石名是拿**存档**按位对齐贴上去的，游戏内背包一旦变过（融合/买卖/换装）
    就会错位 —— 错位意味着「你看着是这颗、改的是那颗」，所以每次操作前都提醒一下。
  · **「商店刷新一轮稀有宝石」按钮不再自己弹“已刷新”**（r4 修）：以前它在注入**失败**时也照样弹，
    等于替你报了个假成功。现在提示与日志都按**真实结果**来 ——「已执行：…」或「执行失败：<原因>」。
  · **每次注入都会在日志里留一行现场**（r4 新增）：命令名 + 宿主地址 + 执行器地址 +
    执行器金币 + 结果。若这个按钮在你的机器上会闪退，请把日志里这一行发回来 ——
    它能直接分清是「命令根本没送到游戏」还是「游戏自己执行时崩的」，省一整轮来回。
  · 本次改动都在宝石页 + 注入提示，其它功能逻辑未动。

★ 宝石页写入链路（上一版）—— “改了没反应”的问题已修好，现在能真正改到存档。

  根因两条，都已修：
  ① 训练器读一次就把地址记下来，之后写的是**已经失效的旧地址**。游戏会把宝石数组
     重新分配（一次会话里实测挪了 5 次），而回读校验照样“通过”，于是表现为
     「日志说写入成功、游戏里毫无变化」。现在**每次写入前都会当场重新定位**，
     对不上就拒绝写入并提示你重新读取。
  ② 加法型宝石的 GemTier **只在 CookedGemVar=50（进过熔炉）时才被游戏承认**。
     cook=0 的宝石，游戏在切场景重建背包时会把 tier 归零。现在训练器改 tier 时
     会**自动把该宝石标记为“已融合”**。
     受影响的 15 个模板：UberAttackGem / UberHealthGem / UberShieldGem / UberMagicGem /
     8 种元素 Uber*Gem / UberElementalAttackGem_100 / RainbowElementalAttackGem_100 /
     UberBossBoostGem。宝石页里都能改。

  ⚠ **两条硬约束，请务必照做，否则改动会“看起来没生效”**：
  · 改完**不要先切到游戏里打开宝石界面** —— 那会让该数组卸载重载，未落盘的改动被冲掉。
  · **界面会立刻变**（实测那个数组就是游戏 UI 直接读的那一份），但要**存进存档**需要：
    切一次场景（进熔接室再退出即可），或等游戏约 50 秒的自动存档。

【功能总览】
· 战斗·商店：无敌 开/关、充满超能魔法、击杀当前Boss（仅战斗中）、
  全招架宝石 开/关（**改写配置文件**，不是内存：改完须重启游戏）、
  金币/筹码（自动绑定，填目标值直接写入）、商店刷新、触发龙战/收藏家
  · 收藏家两件事**互不相干**，别混：
    「起始武器索引」= `setupcollector` 的参数（决定他用哪把武器/给哪个奖励）。
      ⚠ **这个数字就是"奖励阶梯的起点"**（作者 2026-10-09 实测修正：旧说法"0=默认走游戏自身进度"**是错的**）：
      **每次触发都从它开始** ⇒ 填 0 就是每次都从列表第一件开始（他实测"第二个收藏家还是初始装备"就是这个原因）。
      想按列表逐件拿，就依次填 0、1、2、3…（列表：`Sword_205, Sword_414, Sword_638, Sword_330, Sword_506, Sword_36, Sword_234, Sword_413`）。（1.x 有这个框，2.0 重写时丢了写死 0，本版补回。）
      ⚠ **参数语义（作者 2026-10-09 实测定论）**：它就是**"已获得奖励数"**（0 基）—— 填 `0` 打第 1 把、
      填 `1` 打第 2 把……（实测：`0`、`1` 都能正常召唤；`2` 在当时的存档状态下**一直召唤不出来**，原因待查）。
    · **触发后什么时候生效**（2026-10-09 共同解码 `SwordPC.GenerateRandomWorld`）：**下次进图/读完档时**，
      在**全图刷怪点里随机挑一个**强制替换成他（其余刷怪点照常刷各自的怪）—— 所以：出现的**位置**每图都变，
      有时在第 1 个怪的位置、有时在第 2 个，而别的位置该是普通怪就是普通怪、该是龙就是龙 ✓ 这**不是**连带效果。
    「设置当前敌人等级」= 独立按钮（不写参数）：把**当前在场的敌人/Boss**的等级设成
      **当前场景的怪物等级**（实时读取，见下面「怪物等级怎么读的」）。
      · **为什么不是玩家等级**：玩家等级一般不代表战斗难度 —— 高周目下真正抬高敌人等级的
        是身上带的 `UberBossBoostGem`（每颗可加数万级），而玩家每周目等级上限只加三位数。
      · **时机：他出场后、你去点他开打之前点**（2026-10-09 作者实测纠正：**战斗中改不了** ✗）——
        `setbosslevel` 写的是"当前 Boss"，而他**站在图里等你点他时就已经是当前 Boss** ✓。另：
        收藏家还没出场，发了也打不到他（作者实测：触发后连打几场没见到他，还在**兽形怪
        场景**把面前那只怪换成了**黑模型** —— 说明替换确实响应了，只是该场景的刷怪位
        装不下人形怪）。
        ⇒ 正确流程：**触发置位 → 走到能刷人形怪的场合、等符合条件的战斗 → 他出场后再点
        这个按钮**。仅对当前这一场有效（下一场重新生成时按原版表重算）。
    · **刷不出来就是“本血脉已经用掉那次”**（原版设计：`CollectorCanSpawn()` 要求
      `GetCollectorItemsTakenThisPlaythrough() < MaxCollectorItemsPerPlaythrough`，ini=1）。
      解法 = 点「**清零收藏家进度**」按钮（把真身 `+0x3E6C` 写 0）→ 他下次就能再出场，
      **不用关游戏、不用碰存档**。⚠ 该偏移是 Siris 的（当前角色是 Isa 时无效，需另行定位）。
    · ⚠ 若你**手工改存档**：必须同时更新 `Cloud\LocalFileHeaderCache` 里该文件的 40 位 SHA1
      （= `SHA1(解密体[0:contentLen])` 小写），否则游戏会**静默回退**到 `_BackupX_*.bin`
      —— 看起来就是“改了没用”。详见《宝石研究/03_存档迁移.md》。
    · 等级要真抬高得改 `SwordGame\Config\DefaultGame.ini` 的 `CollectorLevel[]`
      （原版阶梯 50…15000，**不随你的等级/世界等级走**）并重启游戏。

【怪物等级怎么读的】（2026-10-09 差分定位实证；**不需要手工定位**）
  游戏里显示的敌人等级 = **原始掷点等级 + 宝石加成**（每颗 `UberBossBoostGem` 按其自身的
  "Boss 等级 +N" 数值叠加），而且**在加载那一刻固化**：已加载的怪不会因为换宝石而变，
  拆掉宝石后只有"下一只刷出来的怪"才变（实测：194378 − 64750 = 129628，而下一只是 129602，
  差的 26 就是掷点波动）。
  修改器读的是**当前场景的等级数据对象**：它随场景换堆内存，但**指向它的两个全局变量在游戏
  映像内**（本游戏无 ASLR、映像恒在 0x140000000）⇒ 读法是一条固定指针链
  `[[映像基址 + 0xCE3588] + 0x7B0]`，**不用扫描、也不用你填任何参数**。
  读不到时（例如停在标题/加载界面）会明确提示"没读到怪物等级，未发等级"，
  绝不拿玩家等级或猜的值顶替。
· 物品发放：按分类浏览全部物品；选中后点「发放选中物品」按类型走正确通道：
  装备/藏宝图=直接发放（未拥有才发）；宝石=刷进随身商店（去商店购买即入袋）；
  材料/药水/钥匙/抽奖箱=消耗品通道直接加数量
· 宝石·背包：列出背包与随身商店里的全部宝石（模板名 / Tier / 融合标记 / 随机加成 /
  当前显示值 / 地址），可把某一颗改成目标显示值或目标 Tier。
  请先进入**能看到背包宝石的界面**再点「读取背包」——背包数组只在特定界面装载，
  界面不对时它会明确提示，不会乱猜。
· 成长：体力/护盾/攻击/魔法/等级/技能点/生命/最大生命的 读取 / 写入 / 锁定（读后写冻结）
  掌握升阶：把所有物品推到目标等级并掌握（⚠只升不降，建议先用测试档验证）
· 发现模式：通用内存扫描工作台（首扫/筛选/快照/差分/试写），供进阶排查
· 换存档：修改器会自动检测并重新绑定（日志出现“自动重新绑定完成”后再操作）
· 首次运行 / 换版本后第一次启动：会弹一次「开发者信息 + 本版更新」窗。
  里面只有**一句话摘要**（新增/修改/删除），不铺整段 changelog；想看细节点「完整更新日志」

【常见问题】
Q: 提示“注入器未就绪”？
A: 等几秒让自动附着 + 自检完成；或点「立即附着」。
   若一直如此，请把日志发回（可能你的游戏版本与本文档不一致）。

Q: 物品发放 / 掌握升阶没反应？
A: ① 看日志有没有黄字「UPK 校验未通过」；有就点「部署/校验 UPK」（先关游戏）
   ② 确认游戏没在读档/加载中
   ③ 确认发放的是游戏里当前条件下允许的动作（例如装备“已拥有”时不会重复发放）

Q: 宝石页提示“写入取消：…”？
A: 这是**安全闸**在起作用，两种情况看日志那句话的后半段就能分清：
   · 「背包(+0x1FEC)/商店(+0x1FFC)两个数组当前都是空的（Count=0）」→ **不是故障**。
     玩家在关卡里 / 商店熔接室界面时，背包数组会被游戏卸载。
     回到**藏身地主界面**（能看到宝石背包那个界面）再点一次「读取背包」，然后立刻改。
   · 「…已失效（游戏重分配过）」→ 游戏把数组重新分配过了，旧地址不再有效。
     重新点一次「读取背包」再操作即可。
   两种情况下都**不会**写到错误的位置——宁可不动，也不乱写。

Q: 点「填上限」没反应，提示“上限不清楚”？
A: 这是**有意的**（本版新增）：**上限说得清才自动填**。
   · 加法型（模板有 RecipeBoostAmount）→ 上限 255（GemTier 是 uint8 字段，255 就是硬上限）
   · 下标型（模板有 UpgradeTier[]）→ 上限 = 档位表长度（如 FireGem 是 5、ItemDropGem_1 是 3）
   · 模板两者都没有（以及商店里的「(空槽)」）→ 本页**不知道**它的上限，
     就不会拿 255 之类的数字顶替（上一版会填 255，看着很确定、其实是猜的），
     提示里会说明原因，请自己填一个目标值。
   另外：「显示数值」模式下，若模板没给 MaxRandomAddPct（pct 能掷到多少不知道），
   或基数没查到，也会判为“说不清”——因为那种情况下的上限同样是算不出来的。

Q: 宝石改完界面变了，但重进游戏又变回去了？
A: 落盘没赶上。按上面的硬约束：改完**立刻切一次场景**，中间不要打开宝石界面。
   另外注意该宝石的模板是否属于“加法型 15 种”之列——不属于的话游戏会忽略它的 tier。

Q: 某项成长属性显示“未定位”？
A: 本版应全部自动绑定。若出现，说明结构偏移与你的游戏版本不符——
   可临时用该行的「定位」按钮手工绑定（填游戏内当前值→定位→游戏里改变数值→填新值→再定位），
   并把日志发回，我会按你的版本修正偏移。

Q: 首次运行，四维/等级显示「未定位」，金币/筹码好像也不对？
A: 这是"还没绑上真身"。内存里玩家类有多个实例，**只有 1 个装着背包/商店数组**，其余是空壳；
   训练器现在会拒绝绑定空壳，且每 2 秒自动重试一次。
   · 若游戏还在读档中、或你正在关卡里/商店熔接室界面 → **属正常**。回藏身地主界面，最多 2 秒自动绑好，
     不需要手动操作（日志会写一行「未绑定真身：…」说明原因）。
   · 若回到藏身地后一直不好 → 把日志里那行「未绑定真身」以及开头的「注入器自检」整段发回。

Q: 换电脑 / 换游戏目录？
A: 重新点「游戏目录…」选择即可（upk 按 md5 判断是否需要替换）。
