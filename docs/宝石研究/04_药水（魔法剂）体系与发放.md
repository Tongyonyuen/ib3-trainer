# 04 · 药水（官方中文「魔法剂」）体系与发放

> 2026-10-10。本文解答"**怎么发放指定药水**"，并纠正一个此前流传的错误结论。
> 所有结论标注 **【实测】** / **【推断】**。工具产物见文末。

---

## 一、一句话结论

**游戏里有两族完全不同的「药水」，此前一直被当成一族 —— 这是所有困惑的根源。**

你要找的那种（野外捡到 / 坩埚合成的「魔法剂」）是 **A 族：`DefaultGems.ini` 里的 8 个 `Potion_*` 模板**，
它的类**不是**药水类，而是**宝石类** `SwordInventoryItemGem`（只是 `ItemType=SIT_Potion`）。

| | **A 族：魔法剂（你要找的）** | **B 族：体力回满那类** |
|---|---|---|
| 类 | `SwordInventoryItemGem` + `ItemType=SIT_Potion` | `SwordInventoryItemPotion` |
| 模板定义处 | **`DefaultGems.ini`**（8 个 `Potion_*`） | `DefaultPotions.ini`（**只有 1 个** `TRA_Potion_HealthL`） |
| 标识 | **`GemName`**（如 `Potion_HealthRegen`） | `NumConsumable[29]` 计数 |
| 中文名 | 由本地化 `Gems` 段的生成模板拼出（`%type% 属性魔法` 等） | `FriendlyName=体力回满` |
| 发放通道 | 宝石 / 坩埚通道 | **`addconsumable 29`** |
| 走不走 `NumConsumable` | **不走**（没配 `BattleEffectRewardType`） | 走 |

### A 族 8 个模板（`DefaultGems.ini` 与用户侧 `SwordGems.ini` 里都有；本节字段逐个核对过）【实测】

| 模板 | 效果 | PotionType |
|---|---|---|
| `Potion_HealthRegen` | `BE_PlayerGetHealth` +10（`BattleEffectRetriggerTime=1.0`） | 1 |

| `Potion_UnlimitedDodge` | `BE_PlayerGetDodge` +5（retrigger 0.5） | 2 |

## 二、根因：为什么此前只找到「体力回满药水 / 钥匙 / 地图 / 抽奖箱」

那条通道是 **`SwordPlayer.AddConsumable(Consumable, AddCount, bIgnoreMax)`**，它写的是
**`NumConsumable[Consumable]`**，而下标来源是：

```
SwordInventoryConsumable.GetConsumableType()  →  return BattleEffectRewardType
```

**A 族 8 个模板全都没有 `BattleEffectRewardType` 这个键** → `GetConsumableType()` 落到默认 0
→ `NumConsumable` 里**根本没有它们的计数**。

⇒ 在 `addconsumable` 那张表里翻找 A 族魔法剂，等于**在 B 族的表里找 A 族的东西**，必然一无所获。

### 顺带解开两个旧疑点

- **`addconsumable 30` 灌了数量也不可见**：`eTouchRewardActor[30] = TRA_Potion_Fixed`，
  而它**没有任何 ini 段、无实体**。旧文档写"30 是材料起始号"是错的（`TRA_World_1_Cactus = 31`）。
- **旧结论「`Potion_ParryAll` 是废弃内容、发不出来」是错的**（2026-10-10 更正）：
  用户存档里就有 3 瓶。当时只查了"有没有配置引用 / 有没有本地化名"，漏了
  **坩埚配方表是硬编码在 upk 里的**（见第四节）。

## 三、数据模型

### 3.1 药水实例的字段布局 = `SwordPC.PlayerGemData`（ScriptStruct）【实测】

`InActivePotionList` / `PlayerUnequippedGems` / `CurrentStoreGems` / `PlayerInventory` 的元素
**共用同一结构**（存档里逐字段比对一致）：

| 字段 | 类型 | 语义 |
|---|---|---|
| **`GemName`** | Name | **主标识**（模板名，如 `Potion_HealthRegen`） |
| `GemTier` | Byte | 档位 |
| `CookedGemVar` | Byte | 熔接/调制变体号 |
| `RandomAddPct` | Float | 随机附加值（决定数值强度） |
| `bShowBadge` | Bool | 新物品角标 |
| `Boost` | Byte | 配方加成 |

- **没有数量字段** —— 数量 = 数组里同名元素的**条数**（实测同模板可重复出现）。
- `(PlayerSavedDataType, PlayerSavedDataIndex)` 是**运行时对象** `SwordInventoryConsumable` 上的槽位指针
  （1=ACTIVE / 2=INACTIVE），**不落存档**【推断：由反汇编里 `PlayerSavedDataType <- IntOne` / `<- Byte(2)` 推出】。

### 3.2 存在哪（`Cloud\*_SwordSaveX_*-0.bin`）【实测】

| 存档字段 | 内容 |
|---|---|
| `InActivePotionList` | `TArray<PlayerGemData>` —— **A 族魔法剂的主存处**（本质是"坩埚产出列表"，也装宝石） |
| `ActivePotions` | 同结构；本档为空 → UE3 不序列化，**二进制里搜不到这串** |
| `CurrentStoreGems` / `PlayerUnequippedGems` | 同结构 |
| `PlayerInventory` | 物品模板数组（`ItemName` / **`NumberPlayerHas`** / `ForgeLevel` / `ItemState` …） |
| `NumConsumable` | 稀疏 `TArray<int>`，**索引 = `eTouchRewardActor` 枚举值** |

## 四、坩埚调制链路【实测（反汇编 + upk 默认属性）】

| 函数 | 作用 |
|---|---|
| `SwordPlayer.CompleteBrewingPotion(CauldronIdx)` | 读 `PotionCauldron[Idx].Reagents`(Byte[]) → 排序 → `CheckForPotionRecipe(...)`；命中则 `GetFixedPotion(RecipePotionFullName)`，未命中则按 `GemCookedMin/MaxValueScale` 等**随机缩放出**一颗 |
| `SwordPlayer.CheckForPotionRecipe(...)` | 遍历 `SwordPlayer.PotionRecipes`，比对 `PotionRecipe.SortedRecipeList` 与手头 `SortedReagents`，命中吐出 `PotionResult` |
| `SwordPlayer.GetFixedPotion(name)` | 转调 `GetFixedGem(name, PC, None, ForcedType=14 /*SIT_Potion*/)`，再 `SavePotionInstanceToPotionList` **入袋** |
| `SwordPlayer.SavePotionInstanceToPotionList(potion, …)` | `PlayerSavedDataIndex = InActivePotionList.Num()` → append 进 **`InActivePotionList`**（**药水入袋的唯一写口**） |
| `SwordPlayer.CreatePlayerPotionList(bActiveOnly)` | 由存档数据批量实例化药水对象（`ActivePotions` 置 Type=1、`InActivePotionList` 置 Type=2） |
| `SwordPlayer.MoveSavedPotionToActiveList(...)` | 存档药水 → 激活列表 |
| `SwordPlayer.GetPotionEffect(potion)` | → `CreateBattleEffectFromConsumable`（战斗效果） |
| `SwordPC.MapPersistentData.GenPotions` | 地图级"已生成几瓶"计数，**不是发放原语** |

### upk 里硬编码的 7 条 `PotionRecipe.PotionResult`（无任何 ini，只存在于 upk 默认属性）【实测】

```
UberSwitchClass
Potion_HealthRegen 0
Potion_HealthRegen 2
Potion_HealthRegen 3
Potion_ElementalDefense
Potion_ParryAll
UberElementalAttackGem
```

格式 = **`<模板名> <档位>`**，由 `SwordInventoryConsumable.GetNameAndTierFromString` 反解
（**空格**为分隔符）。⇒ 这就是 `Potion_ParryAll` 的真实来源。

**存进 `InActivePotionList` 的是 `GemName`（模板名）**，不是生成字符串；
只有**随机生成**的宝石才用 `GetFullGemGeneratedName` + 本地化模板（`StatPotionName` /
`ElementalDamagePotionName` / `GenericPotion` / `PotionName=%type% %effect% 魔法`）拼**显示名**。

## 六、`TRA_Potion_*` 那 8 个（B 族）是**死文本**【实测】

`TRA_Potion_HealthL/M/S`、`HealthRegen`、`HealthRegenL`、`ShieldRegen`、`EasyParry`、`DoubleXP`
这 8 个类为 `SwordInventoryItemPotion` 的模板，**只存在于 `SwordGame.chn`**：

- upk 32471 个导出里，名字以 `TRA_` / `Potion_` 开头的 = **0 个**（`SwordInventoryItemPotion` 类下只有 CDO）。
- 全游戏目录 grep：其余 7 个只命中本地化文件，**任何 Config ini 都没有**。
- 这批模板走 UE3 的 config 段驱动（`[模板名 类名]` 段运行时 `StaticConstructObject`）——
  **没有 ini 段 = 永远不实例化**。

同类规律：`TRA_Key_*`→`DefaultKeyItems.ini`、`TRA_World_N`→`DefaultWorldItems.ini`、
`TRA_GrabBag_*`→`DefaultRandomItems.ini`；而 `TRA_Potion_Fixed` / `TRA_Gold_*` / `TRA_Gem_Fixed` /
`TRA_Item_Fixed` / `TRA_Chips_*` **无任何 ini 段**（枚举里占位但无实体）。

⇒ **B 族实际只有 `TRA_Potion_HealthL` 一个是活的。**

## 七、关于「魔法剂在代码层面不是消耗品」这个假设

**不成立**（严格意义上）：

```
SwordInventoryItem
 └─ SwordInventoryConsumable          ← GemTier / CookedGemVar / RandomAddPct / BattleEffect /
      │                                  BattleEffectRewardType / GeneratedName / GetSaveData()…
      ├─ SwordInventoryItemGem         ← 宝石（**A 族魔法剂在这里**）
      ├─ SwordInventoryItemPotion      ← B 族魔法剂
      ├─ SwordInventoryItemKey
      └─ SwordInventoryItemWorld / ItemRandom / BattleChallenges / PlayerAbility
```

`SwordInventoryItemPotion` 与 `SwordInventoryItemGem` 是**兄弟**，都属消耗品分类。

**但直觉抓对了一半**：**A 族魔法剂确实不走 `addconsumable` / `NumConsumable` 那条计数通道**
（因为没配 `BattleEffectRewardType`）。准确表述是
「**宝石系魔法剂不是 `NumConsumable` 计数的可堆叠消耗品**」，而不是「不是消耗品分类」。

> `SwordInventoryConsumable.GetFriendlyName.bPotion` 的真相：它 = `(ItemType == SIT_Potion)`，
> 只是个**显示开关** —— 为真时把本地化键从 `*GemName` 换到 `*PotionName`
> （`Gems` 段里两组键成对存在）。**不构成分类隔离。**

## 八、发放指定魔法剂：途径对比

> **两条主力路线均已于 2026-10-10 游戏内实测通过**，实测记录见第四节末「实测记录」。

| 途径 | 定向？ | 前提 | 评价 |
|---|---|---|---|
| **`getfixedpotion <名字> [档位]`**（给 `SwordPlayer.GetFixedPotion` 补 exec 位） | ✅✅ | 原版函数，**形参只有 1 个 `Str`、无 out-Struct**（不会重蹈 `CreateFixedStoreGemFromName` 控制台喂不进 struct 的覆辙） | **首选**✅ 实测。体内 `GetFixedGem(名,…,ForcedType=14)` → `SavePotionInstanceToPotionList` → **直接进 `InActivePotionList`**，不用买 |
| 商店路线 `setplayercreatenewlistofstoregems 1 <模板名> 1 <数量> 1` | ❌ | **零改造**；第 3 参 `bCreatePotions=1` 确实走了药水分支 | ❌ **实测 UI 层失败**：药水条目确实进了 `CurrentStoreGems`（存档可见 42 条 `Potion_HealthRegen`），但**随身商店把它显示成「宝藏宝石」式的兜底占位**（无属性 / 无效果 / 不可镶嵌）⇒ **该路线对药水不可用** |
| `setplayerpotions` | ❌ 随机 | 零改造 | **会先清空你现有药水**再刷店；进的是商店要买。**别随手用** |
| `setplayergiverandomgem`（按成本钓鱼） | ❌ 近似 | 零改造 | 不推荐 |
| `CreateFixedStoreGemFromName`（含 `bPotions` 分支） | ⚠️ | 已 exec | 体内两次 `GetRewardTreasure` **硬编码 `eType=15`（宝石）**；且 out-Struct 形参**在控制台解析层就被卡死**（改参数顺序也救不了）。**不要依赖** |
| 直接改存档 / 内存写 `InActivePotionList` | ✅ | 结构已知（六字段） | 风险最高：存档有 SHA1 校验（`LocalFileHeaderCache`，见 `03_存档迁移.md`） |

### 首选方案的注意点

- `GetFixedPotion` 的**入袋那一步被 `SwordPlayer.bGiveTreasureItem` 门控**，
  需确认游戏内该标志为真（正常游玩时应为真）【推断】。
- 要发"自定义 / 新"魔法剂，可在 `DefaultPotions.ini` 或 `DefaultGems.ini` 加模板段，
  再按名发放；**新模板能否被原生加载器按名找到需实测**。

## 九、实测记录（2026-10-10，游戏内，测试副本 `E:\IB3`）

### 9.1 前置：给 `SwordPlayer.GetFixedPotion` 打 exec 位

| 项 | 值 |
|---|---|
| 包 | `E:\IB3\SwordGame\CookedPCConsole\SwordGame.upk`（**主游戏 `Ⅲ` 未动**） |
| 补丁点 | 文件偏移 **`0x644D38`**（`GetFixedPotion` 的 FunctionFlags 第 2 字节），`0x00` → `0x02` |
| FunctionFlags | `@0x644D37` `02 00 02 00`（`0x00020002`）→ `02 02 02 00`（`0x00020202`） |
| md5 | `25e89f5a9e0d1e4a1c273d284df4173d` → `78648e63851523719adf1544d71cd471` |
| 备份 | `SwordGame.upk.bak_1010_getfixedpotion` |

⚠️ **该 8 字节锚（`02 00 02 00` + 前 4 字节）在全包出现 3103 次**，扫模式补丁不可靠 ——
本偏移是从**导出表**直接读出来的（`umodel_list.txt` 里 `SwordPlayer.GetFixedPotion` 的 off+size），
**只对 md5 = `25e89f5a…` 这一版有效**，打前必须校验 md5。

### 9.2 路线 1（零改造）—— 能刷进商店，但还要买

```
setplayercreatenewlistofstoregems 1 Potion_HealthRegen 1 1 1
```

- `CurrentStoreGems`：**132 条普通宝石 → 42 条 `Potion_HealthRegen`**（全 `GemTier=0`）【实测】
- `InActivePotionList`：**不变**（仍 10 条）⇒ 进的是随身商店、不是袋子
- `bCreatePotions`（第 3 参）= 1 确实让 `CreateFixedStoreGemFromName` 走了药水分支并用名字造出了药水对象

**❌ 但 UI 层不成立【用户 2026-10-10 实测】**：随身商店把这些条目显示成**「宝藏宝石」式的兜底占位**
（无属性 / 无效果 / 不可镶嵌）。

⇒ **`CurrentStoreGems` 严格是"宝石列表"，商店 UI 按宝石模板表解析每一条；`ItemType=SIT_Potion`
的条目解析不出来就落到兜底显示。** 一般化结论：
**别往 `CurrentStoreGems` 塞非宝石**（塞了不会报错，只会变成不可用的占位物）。

> 附带核查：`RARE TREASURE GEM` 这个串在游戏目录里**一处都搜不到**（Config、IB3.exe、upk、
> 本地化全搜过；也搜过 UTF-16 编码），所以它不是某个模板名，而是**运行时的兜底显示**。

### 9.3 路线 2（首选）—— 直接进袋子 ✅

```
getfixedpotion Potion_HealthRegen        → InActivePotionList[10]  GemTier=0
getfixedpotion Potion_HealthRegen 2      → InActivePotionList[11]  GemTier=2   ★带档位也吃
getfixedpotion Potion_ParryAll           → InActivePotionList[12]
getfixedpotion Potion_SecondChance       → InActivePotionList[13]
getfixedpotion Potion_ElementalDefense   → InActivePotionList[14]
```

- `InActivePotionList` 逐次 **+1**，条目字段：`GemName=模板名`、`GemTier=` 参数（默认 0）、
  `CookedGemVar=0`、`RandomAddPct=0.0`、`bShowBadge=True`、`Boost=10`
- 前后存档差分**除该条目外无其它变化**（只有地址整体后移）
- ⇒ **`getfixedpotion <模板名> [档位]` = 按名发放任意魔法剂并直接入袋**。
  名字里带空格能被控制台整体吃进那一个 Str 形参（`<模板名> <档位>` 是 `GetNameAndTierFromString` 的格式）

### 9.4 观测手法（可复用）

```
sendcmd.exe "dumpunencryptedsavefile <名字> 0 0"   → 写 Binaries\Win64\<名字>0.bin（明文，不动 Cloud\ 真档）
```

`DumpUnencryptedSaveFile` 的**真序 = `<SavedFileName:Str> <Index:Int> <bDeleteSave:Bool>`**
（导出表子属性定序；`bDeleteSave` 在**最后**，写 0 安全）。
⚠ 该 dump 比 `decsave.exe` 解出来的明文**多 4 字节前导**（`05 00 00 00`），
用 `_tmp\flatwalk.py` 解析前要先切掉这 4 字节。

### 9.5 使用（喝掉）之后的行为【实测】

游戏里喝掉一瓶之后：`InActivePotionList[11].GemName` 被置成 **`None`**（**墓碑，不立刻压缩数组**；
下次存档时才真正移除并前移），同时**复制出一条到 `ActivePotions[0]`**（`GemName` / `GemTier` 原样带过去）。

⇒ 两个列表的分工：**`InActivePotionList` = 未使用（库存）；`ActivePotions` = 已使用、本场战斗生效中**
（`TriggerBattlePotions` 把后者变成战斗效果）。这也解释了为什么没喝药时 `ActivePotions` 在存档里搜不到（UE3 不序列化空数组）。

### 9.6 ★ 可发放范围 = 看模板有没有 `PotionType`

`getfixedpotion` 能否成功，**取决于该模板是否定义了 `PotionType`**（`SwordInventoryItemGem.PotionType`）。
实测分离得很干净：

| | `PotionType` | 结果 |
|---|---|---|
| `FireGem`(4) / `AttackGem`(4) / `UberElementalAttackGem`(2) / `UberBossGem_3`(2) / `UberSwitchClass`(2) | 有 | **全部成功** |
| `UberFireGem` / `UberAttackGem` / `UberMagicGem` / `UberElementalGemMax` / `RainbowElementalAttackGem` / `UberIceGem` / `UberLightGem` / `UberGoldGem` / `UberXPGem` | **无** | **全部失败**（静默，不报错） |

`DefaultGems.ini` 共 164 个模板 → **90 个带 `PotionType`（可发放），74 个不带（不可发放）**。
完整清单见 **`参考资料/可发放药水模板清单.txt`**。

- 8 个专用 `Potion_*` 都在其中（PotionType 1~4）。
- 其余是**把宝石模板强制成药水形态**，显示名由本地化生成模板拼出 ——
  例：`FireGem` 强制成药水后，游戏里显示为 **FIRE ATTACK POTION**（实测）。
- **元素族可用的**：`FireGem`/`IceGem`/`ElecGem`/`PoisonGem`/`LightGem`/`DarkGem`/`WaterGem`/`WindGem`
  与基础族 `HealthGem`/`ShieldGem`/`MagicGem`/`AttackGem`，以及 `UberElementalAttackGem`。
  ⚠ **Uber 级元素宝石（`UberFireGem` 等）没有 `PotionType`，发不出来**。
- 档位：`getfixedpotion <名> <n>` 的 n 写进 `GemTier`（实测 0 / 2；界面显示数值随档位变：
  生命恢复 tier0→每秒100、tier2→每秒1000、tier5→每秒12500）。
- 容量：`SwordPlayer.MaxPotionCount` 默认 **10**，由技能加成抬高（`GetMaxPotionCount` =
  `GetModVarBool(84) ? MaxPotionCount+3 : MaxPotionCount`）；用户实测其清单容量为 **30**。
  清单满时 `getfixedpotion` 同样**静默失败**（有 `HasFullPotionInventory` / 游戏内"魔法剂清单已满"提示）。

### 9.8 三条追加实测（2026-10-10 下午）

**① `BattleEffectRetriggerTime`（按秒重复触发）是药剂专属机制**【实测】

全游戏**只有 3 个模板**带这个字段，**全部是 `Potion_*`**：

| 模板 | 间隔 | 效果 |
|---|---|---|
| `Potion_HealthRegen` | 1.0 秒 | 每秒回血（游戏里那瓶「RARE HEALTH POTION」） |
| `Potion_ShieldRegen` | 2.5 秒 | 每 2.5 秒回盾 |
| `Potion_UnlimitedDodge` | 0.5 秒 | 每 0.5 秒回闪避 |

**没有任何宝石模板用它** —— 宝石只能靠 `BT_OnParry` / `BT_OnBlock` / `BT_OnDodge` / `BT_OnCombo`
这类**事件**触发。⇒ 修正此前"任意宝石模板都能当药水"的说法：**机制上**都能造（90 个带 `PotionType`），
**效果语义上是两类东西**（按秒持续 vs 事件触发）。

**② `PotionType` 只是图标选择器**【实测】

全游戏只有 `SwordInventoryItemGem.GetDefaultIconPath` 读它，拿去做
`SwordGemIcons.PotionSubTypeIcon[PotionType]` 选小瓶图标。**不参与效果、不参与数值。**
（但它是 `getfixedpotion` 成功的前提。）

**③ 那句 ×10 的归属：`Boost` 字段 vs `GemToPotionValueScale`（**未定论**）**【实测数据 + 待确认】

存档实测各数组实例的 `Boost` 字段：

| 数组 | `Boost` |
|---|---|
| `PlayerUnequippedGems`（宝石） | 0（12 条）、16（1 条） |
| `CurrentStoreGems`（宝石） | 0（42 条） |
| `InActivePotionList`（药水） | **10（21 条，全部）** |

药水恒 10、宝石恒 0，而药水显示值恰好 = 档位表值 ×(1+pct) **×10** ⇒ **那句 ×10 很可能就是实例上的
`Boost` 字段**，而不是 `SwordPlayer.GemToPotionValueScale`（默认也是 10.0）。

**判别实验（已设计，未做）**：把某瓶药水的 `Boost` 改成 20，若显示值翻倍 ⇒ 是 `Boost`；
若不变 ⇒ 是全局 `GemToPotionValueScale`。
（注意 `GemToPotionValueScale` 的反查结果只命中**费用**计算：`SwordInventoryItemGem.GetCost` /
`SwordInventoryItemPotion.GetMaxCost` / `CompleteBrewingPotion` / `GetRandomPotion`，
**没有**命中任何显示值函数。）

**对修改器的影响**：无论归属如何，那句 ×10 都是常量，折进公式即可 ——
`GemTier`（档位）+ `RandomAddPct`（随机加成）两个字段已能覆盖几乎任意数值
（如 `DarkGem` 档位 1..5 × pct 0..1 → 50…4000）。若最终证实是 `Boost`，则**又多一个单字节的细调旋钮**（0~255 倍），
"指定数值"会更好做。
