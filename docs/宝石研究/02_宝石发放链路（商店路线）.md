## 五、GEM 发放链（活体代码破译，直入背包路线参考）

### GetRandomGem（exec7 起可调；6 参：RewardLevel, GoldScale, GoldValue, PrefGemType, ForcedType, bDontSaveToList）
```
1. 按 GoldScale/档位 从池中取模板 → DefaultGem（GetValueBasedRandomItem）
2. SpawnedGem = DefaultGem.CreateItemInstance()
3. SpawnedGem.RandomGenerateData(...)   ← 掷 GemTier/CookedGemVar/RandomAddPct
4. if (!bDontSaveToList) self.SaveGemInstanceToUnequippedList(SpawnedGem, True, <默认>)
5. Return SpawnedGem
```
- `SaveGemInstanceToUnequippedList(GemItem, bAllowToFail=True, bUpdateBadges=默认)` = 入袋（未装备宝石列表）。
- 参数顺序规则（本次多重校准）：**控制台/声明序 = paramd(all_funcs)清单的反序；字节码实参流 = 声明序**（SCG/FCGN 调用点逐字节核对）。
- 相关签名（真序）：
  - `CreateFixedStoreGemFromName(GemName:Str, FixedGem:out, bHighEndOnly:Bool, bPotions:Bool)`（void；体内 GetRewardTreasure(eType=15) + SaveGemToStoreList）
  - `GetRewardTreasure(eType:Byte, RewardLevel:Int, Treasure:out, GoldScale:Float, ForceDropItemName:Str, FavorRandomType:Byte, FavorScale:Float, bRecursiveCall:Bool)`
  - `LoadGemInstance(GemSavedData:Struct, InPC, ForceType:Byte) → GemItem`（读档路径）
  - `SaveGemInstanceToUnequippedList(GemItem, bAllowToFail, bUpdateBadges)`（入袋）

## 六bis、宝石数值内存直写（2026-10-06 原型已打通，实测有效）

**目标**：把任意背包宝石改成任意数值（如"400 火焰"= tier5 + pct100%）。

**数值公式**（ini 全量核对）：`显示值 = 基础值 × UpgradeTier[档位] × (1 + RandomAddPct)`；
- 例：火焰 = base1 × 阶梯[1,5,25,50,100,200] × (1+pct 0~1.0) → 取值域 1~**400**
- 有 `UpgradeTier/MaxRandomAddPct` 字段的模板共 101 个（元素/攻防/蓄力系=可掷档位）；无字段的 65 个（Uber/暗火/光谱/Gem3_x/泰坦速/药水=固定值）

**内存结构（已定位）**：宝石"掷点记录"= 24 字节/颗：`[+0] RandomAddPct:float32 | [+8][+12][+16] 中间字段(id等) | [+24*] 下一颗`（商店列表与背包 `PlayerUnequippedGems` 都是此结构，各有 2 处镜像副本）。
- 背包记录示例（实测）：0x7FF4E6BE1844 = 背包 slot5（火 0.8216→写 1.0 → 存档确认 tier5 pct=1.0 = **400** ✓）
- 商店记录：全 42 格（6档×7）；**商店列表会被"确定性重生成"**（购买/刷新后还原原掷点）→ 改商店有竞态，**正路=先买进背包再改**。

**已验证流程**：`刷店 → 买 → memtest scan Float <pct> → memtest write <addr> Float <新值>（两处镜像都写） → hideout 触发存档 → decsave 解密验证`。

**坑**：
- 背包=28 上限；存档解析要按 `ArrayProperty` 头的 count 精确切分（背包 count=9 vs 商店 count=42，两节相邻易串读！用户点名）。
- 商店的 pct 值在内存=census 可见（能扫到）；背包中部分旧宝石的 pct（如 0.1729）扫不到（疑懒加载），但**刚买进的宝石可扫到**（0.8216 ✓）。
- tier 字段位置 = 记录 **+0x14（u32）**（2026-10-06 冰宝石实测：{pct,0,0,id,?,tier}，冰 tier=5 在 +0x14 ✓）；改档位组合 = 同时写 +0 与 +0x14。
- 定位新买宝石的实用法：扫描其独特 pct → 命中里找"前一条记录 = 已知背包宝石的 pct"（24B 步长相邻）的那组（=背包数组）；镜像共 2 处，都写。
