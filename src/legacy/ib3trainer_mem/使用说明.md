# IB3 内存修改器 v2 使用说明

独立于控制台注入版（`ib3trainer\IB3快捷修改器.exe`）的**内存直写**修改器：直接 `OpenProcess` + `ReadProcessMemory/WriteProcessMemory` 读写游戏内存，**不弹控制台、不抢焦点、即时生效**。

- 程序：`E:\ib3_re\ib3trainer_mem\IB3内存修改器.exe`
- 源码：同目录 `Ib3MemTrainer.cs`（csc.exe 编译，无运行时依赖）
- 预设文件：同目录 `mem_presets.csv`（自动加载/保存）

## v2 新增（2026-10-06）

| 功能 | 说明 |
|---|---|
| **目标向导** | 顶部下拉框选目标（金币/属性四维/等级/属性点/掌握经验/HP），自动设类型并显示"怎么让这个值变化"的定位流程 |
| **未知初始值(快照)扫描** | **数值框留空** → 首次扫描 = 全内存快照；之后筛选不再需要已知初始值，适合 HP/掌握经验这类不显示数值的目标 |
| **Float 容差** | 等于/未变化 对 Float/Double 用相对容差比较，不再因浮点误差漏值 |
| **撤销写入** | 修改表选中行 → "撤销写入(恢复原值)"：写回首次修改前的原始值（实测 HP/属性时的安全兜底） |
| 修复 | 进程连接不再把"IB3内存修改器"自己当成游戏（改为优先精确名 `IB3` 且排除自身） |
| 修复 | 扫描后切换类型不再让结果列解码错位 |

## 两种扫描模式

### 模式 A：已知当前值（两遍扫描）
1. 目标向导选一个（或手动选类型），填入**当前值** → **首次扫描**（结果可能很多，正常）
2. 回游戏让它变化（买东西/加点/命令改值…）
3. 筛选条件选 **「变化了」** 或 **「等于 新值」** → **再次扫描**，重复收敛到个位数
4. 选中地址 → **添加到修改列表** → 填写入值 → **更新并写入**

### 模式 B：未知初始值（快照）——数值框留空
1. **数值框清空** → **首次扫描**（进行全内存快照，显示快照 MB 数）
2. 回游戏让数值变化（挨打掉血/获得经验…）
3. 筛选 **「减小了/增大了/变化了」**（或已知新值时直接 **「等于 新值」**，更快）→ **再次扫描**
4. 重复直到收敛，其余同模式 A

## 各数值的定位流程（速查）

| 目标 | 类型 | 怎么让它变化 | 备注 |
|---|---|---|---|
| 金币 | Int64 | 控制台 `setplayergold <数额>` 或买卖 | 已验证主线；填 999999999 写值 |
| 属性四维 | **Int32** | 控制台 `setplayerstats <攻击> <体力> <护盾> <魔法>` 或加点 | **2026-10-06 内存实证**：参数顺序=攻击、体力、护盾、魔法；内存中四字段连续排列（体力,护盾,攻击,魔法）；用整数参数；旁边有一组"加成后"副本，写基础值那组最稳 |
| 玩家等级 | **Int32**（已验证） | 控制台 `setplayerlevel <等级>` 或直接改内存 | 字段在 `0x7FF4E8F6xxxx` 族（本次 0x7FF4E8F607F0）；写 42→显示 42 ✓；定位用大值探针 |
| 属性点/技能点 | **Int32**（已验证） | 升级/掌握获得或直接改内存 | 字段与等级同族、相距 0x178C（本次 0x7FF4E8F61F7C）；写 8888→显示 8888 ✓；**升级命令会重算覆盖，改完勿触发升级/掌握** |
| 物品等级 | **Int32，0基**（已验证） | 直接改内存（免锻造！） | 物品结构 +0x10（显示等级=值+1）；实测写 7→显示"等级8"**且属性真实生效**；同结构 +8=经验、+0xC=数量、+0x14=已掌握标志(0/2) |
| 部位掌握经验 | **Int32**（已验证） | `giveweaponxp <XP>`（对应部位）只能填满当前上限不能突破；提上限需锻造或 `masterallowneditems` | **2026-10-06 已验证**定位流：界面读经验上限 R（x/R）→ 扫描 Int32 R → 灌该部位经验 → 重扫差分 → 新地址=经验字段（物品结构间距 0x2C，**经验@+8、数量@+0xC**）。同次运行内可直写：写满=已掌握、写小=显示分数 |
| 玩家 HP | **Int32** | 控制台 `setplayerhealth <值>`（上限=`setplayermaxhealth`），或战斗挨打 | **2026-10-06 实证**：写入 2222222 游戏内确认；两遍扫描「等于新值」收敛 |

## 命令行为实测工具（memtest.exe）

与 GUI 共用同一份 `ScanCore` 引擎（实测的就是交付算法），配合 `E:\ib3_re\sendcmd.exe` 自动注入控制台命令：

```
memtest.exe info                                     — 连接+内存区域统计
memtest.exe scan <Type> <value> [maxHits]            — 一次性已知值扫描
memtest.exe gold <v1> <v2> [writeVal]                — 金币两遍扫描（自动 setplayergold 改值）
memtest.exe stats <f|i> <s1> <m1> <h1> <a1> <s2> <m2> <h2> <a2>   — 属性四维两遍扫描
memtest.exe snapstats <s1> <m1> <h1> <a1> <s2> <m2> <h2> <a2>    — 属性四维快照模式
memtest.exe level <v1> <v2>                          — 玩家等级两遍扫描
```

引擎自检（不依赖游戏）：`enginetest.exe` — 对 `_selftest\memprobe_target.exe` 全流程验证（首扫/筛选/写入/快照/容差），应输出 ALL PASS。

## 已知要点与坑（务必读）

- **地址每次运行会变**（堆地址），预设里的地址是上次运行值，重启游戏后需重新扫描定位。
- **快照模式**：只快照可写+私有内存区（数据堆），按类型大小对齐（Float 按 4 字节）；快照总量上限 1400 MB，超限的大区域会跳过并在日志提示。
- 快照后在筛选前**要么用"等于新值"，要么保证只做过一次改变动作**，否则"变化了"会命中大量游戏自身的计时器数据。
- 首次扫描结果过多时，**换更大、更独特的特征值**能显著减少命中。
- **安全性**：改内存不影响存档加密（游戏存档时自己用正确 AES 持久化）。要长期保存改动，改完后游戏内正常存档一次。
- 冻结（锁定）是持续回写，战斗/读档过程中游戏可能重算该值；若冻结失效，重新点「读取当前值」确认地址仍有效。
- **属性/HP 写入可能被游戏在换装/升级/读档时重算覆盖**，属正常现象——这类值更适合"改后立即用"，而不是长期冻结。

## 与控制台注入版的分工

| | 控制台版（ib3trainer） | 内存版（本工具） |
|---|---|---|
| 原理 | 开控制台注入命令 | 直写进程内存 |
| 生效 | 部分界面受限、需重开背包刷新 | 即时生效、无界面要求 |
| 焦点 | 会短暂抢焦点弹控制台 | 完全不抢焦点 |
| 适合 | 发物品/掌握/等级（命令语义明确） | 数值修改/冻结（金币/HP/属性等） |

两者可同时开，互不冲突。
