# IB3 快捷修改器 使用说明

独立窗口工具，点击按钮即自动向游戏控制台注入对应命令（等效手动打开 `=` 控制台输入），免去重复打字。

- 程序：`E:\ib3_re\ib3trainer\IB3快捷修改器.exe`
- 物品数据库：同目录 `items.csv`（940 条，可自行编辑）
- 源码：`Ib3Trainer.cs`（csc.exe 编译，无需运行时依赖）

> **实测确认（用户 2026-10-05）**：命令真实生效。物品/等级类效果在背包界面**不会实时刷新——关闭背包再重新打开即可看到**。金币等 HUD 数值同理。
> **注入方式（v3）**：点击按钮 → 控制台自动短暂弹出（约 1.5~2 秒）→ 命令注入执行 → **自动收起控制台** → 游戏画面恢复，同时浮窗提示"✔ 已生效 — 关闭人物栏重进查看效果"（浮窗不抢焦点）。
> **键盘注入原理（重要）**：刚打开的控制台会丢弃 WM_CHAR 字符消息，只有 VK 按键事件能激活其输入态——因此采用 **首字符 VK 按键 + 其余 WM_CHAR 直发** 的混合注入。纯 VK 会丢 shift 映射（冒号变分号、下划线变减号），混合方式字符全部精确。
> **exec 文件通道不可用**：`exec <文件名>` 命令本身会执行，但该移植版的文件系统被沙盒限制，绝对/相对/引擎搜索路径/文档目录/Exec 目录全部 FileNotFound——无法实现"写文件+按键触发"的完全无控制台方案。
> **彻底无控制台（风灵月影式）**：需要 DLL 注入直呼游戏 ConsoleCommand（模式扫描 GObjects + 远程调用），属独立逆向工程，当前未实施。
> **焦点提醒**：游戏失焦会自动关控制台。工具在打字前/回车前会各重新聚焦一次；若发送瞬间有其他程序抢焦点导致命令截断，重按一次按钮即可。

## 使用前提

1. 游戏窗口标题以 **Infinity Blade III** 开头（默认即是），程序顶部会显示"已找到"。
2. 控制台键为 `=`（当前已配置）。
3. 发送时工具会自动：打开控制台 → 焦点切到游戏 → 逐字注入命令 → 回车执行。**发送期间窗口会被短暂抢焦点，属正常现象。**

### 物品发放
- **装备类 → giveitemonce <模板名>**：直入背包、任意界面（exec6 包，md5=240246fe）。原 `item` 命令的监听器只在物品列表网格页（SwordItemListScene）上，角色装备页/宝石袋页会静默无效，故弃用。
- **宝石类 → setplayergiverandomgem <RewardLevel> <GoldScale> <FavorSocketType>**：GiveItemOnce 只认装备模板表（宝石是独立的 SwordInventoryItemGem 模板体系），故宝石走原生随机发放。**三参数语义（2026-10-05 字节码逆向 + ini 交叉验证）**：
  - **RewardLevel（第1位）**：宝石世代/档位，小整数（游戏内档位体系 0~4，对应宝石 UpgradeTier 五档）；受玩家进度字段 MaxGeneration 钳制——新档玩家的 MaxGeneration 低，填再大也出高档宝石。
  - **GoldScale（第2位）**：**目标金币价值**（不是简单倍率）。引擎在（按孔位过滤后的）宝石池里用 GetCostCloseToValue 找 Cost 接近该值的模板，窗口内无候选 → **静默失败**。可用值 = 真实宝石 Cost 档位：100000（4颗命中）/ 125000 / 250000 / 300000 / 500000 / 650000 / 750000 / 2500000 / 3000000 / 4000000 / 5000000…（700000 落空因 650k 与 750k 之间的窗口没接住，或目标超窗）。
  - **FavorSocketType（第3位）**：⚠️ **实测为弱偏好，非可靠选择器**（2026-10-05 校准：favor=2 两次发放分别得到六边形 BonusComboGem 和三尖刺 ParryChargeGem；favor=1/4 都得到重武器族；已获宝石 Cost 与 GoldScale 无相关性）——最终发哪颗主要由 RewardLevel 档位池随机决定，favor 仅在有多个同价值候选时起次要倾向作用。**需要"指定模板精确发放"时唯一可靠路径 = GiveGemOnce 函数手术**（见下）。
  - **RewardLevel（第1位）**：宝石世代/档位，小整数（0~4，对应 UpgradeTier 五档），受玩家 MaxGeneration 进度钳制。
  - **GoldScale（第2位）**：与产出宝石的实际 Cost 无直接对应（实测 100000 时产出 Cost 300~60000 的宝石），语义待进一步逆向；对产出影响弱于 RewardLevel。
  - **FavorSocketType 实测产出样本**（RewardLevel=2, GoldScale=100000）：favor=2→三尖刺·招架攻击蓄力297（ParryChargeGem）；favor=4→沙漏·重武器格挡泰坦受伤994（HeavyGem族）；favor=6→方形·火焰攻击750（FireGem）；favor=8→三角形·战斗金币404；favor=1→沙漏·重武器金币125（HeavyGem族）。
  - 指定模板精确发宝石需要"新增导出函数包手术"（LoadGemInstance+Save 合成包装函数），属后续工程。
  - 高级：GetRandomGem 已 exec 化（exec7 包，待部署）：`getrandomgem <ForcedType> <bDontSaveToList> <PrefGemType> <GoldValue> <GoldScale> <RewardLevel>`，ForcedType=强制类型(0=不限)，bDontSaveToList=0 要入包，GoldValue=输出参数填0。
- 主分类：装备 / 收集品 / 宝石；子分类按需求分级（装备：单手/重/双/长柄/盾/盔/甲/戒指/Boss专属；收集品：药水/材料/地图/钥匙/抽奖箱；宝石：孔位1~8）。
- 搜索同时匹配**模板名**和**中文名**。双击列表行 = 直接发放。
- 数量框 = 重复发送次数；宝石奖励等级框 = 随机宝石的档位（默认 50）。
- 中文名来源：`SwordGame/Localization/CHN/SwordGame.chn` 官方中文名（覆盖 609 个模板），其余宝石用宝石列表 CSV 推断名；可在 `items.csv` 自行补充，改完点"重载数据库"。
- 注意：Shield_332 官方名就叫"戒指"（Isa 的戒指占盾位模板），分类仍归盾牌。
- ⚠️ 新发宝石 ForgeLevel=0：发完到"掌握升级"页把全部装备拉到目标等级。
- ⚠️ giveitemonce 名字里的 "Once" 可能带去重逻辑（同一模板只发一次）——若重复发放无效，属命令特性，待游戏内确认。

### 掌握升级
| 功能 | 命令 | 说明 |
|---|---|---|
| 一键全部 | `masterallowneditems 0 <等级>` | ✅ 已实测：界面显示等级、只升不降、不扣金币。**绕过轮回等级上限** |
| **部位直接掌握** | `masterequippedweapon/shield/armor/helmet/magic <等级>` | ✅ **函数手术新增（exec8 包）**：当前使用角色身上装备的对应部位直写等级+经验条，绕轮回上限，任意界面可用，不扣金币。部位：武器/盾牌/盔甲/头盔/魔法(戒指) |
| 全装备等级 | `setplayeritemlevel <等级>` | 合法路径：作用于**当前装备的全部物品**，目标等级会被**钳制到本轮回上限**（填 60 实际变 10） |

**轮回等级上限机制**：装备等级受当前轮回（NG+ 周目）钳制，新轮回=10。`setplayervalidlevel` 实测不能改该上限。**跨上限 → 用「部位直接掌握」或「一键掌握」**（均为直写路径）。

**exec8 包**（md5=faec28eb704111297477f20dcaa9200b）：在 exec6 基础上新增 5 个 SwordPlayer 导出函数（MasterEquippedWeapon/Shield/Armor/Helmet/Magic），内部走 QuickMasterItem 直写路径。这是本项目首次"新增导出函数"包手术成功案例。

## 注入原理

与项目工具链 checkcon/win2 同款：`PrintWindow` 绿线像素检测控制台开关状态 → 自动按 `=` 开控制台 → `WM_CHAR` 逐字下发（22ms/字符）→ `VK_RETURN` 执行。若控制台本已打开，先发 40 个退格清空残留输入行，防止命令拼接。
